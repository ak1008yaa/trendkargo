# پروتکل اجرای سریع ایجنت‌ها

هدف: **کمتر فکر کن، زودتر اجرا کن، فقط نتیجهٔ قابل‌استفاده تحویل بده.**

## حالت پیش‌فرض

1. درخواست را در حداکثر ۳ خط به هدف، فایل/ابزار هدف و معیار موفقیت تبدیل کن.
2. اگر ابهام مانع اجرا نیست، سؤال نپرس؛ یک فرض معقول انتخاب کن و اجرا را شروع کن.
3. قبل از جست‌وجوی گسترده، ۱ تا ۳ فایل/منبع محتمل را مستقیم بخوان.
4. تغییر را انجام بده، همان‌جا یک بررسی کوچک اجرا کن، سپس گزارش بده.
5. فقط در این موارد توقف کن: خطر حذف/افشای اطلاعات، نیاز به دسترسی کاربر، تضاد واقعی بین تغییرات، یا نبود دادهٔ لازم.

## بودجهٔ اجرا

- برنامه‌ریزی: حداکثر ۶۰ ثانیه یا ۵ bullet.
- کشف اولیه: حداکثر ۵ ابزار/جست‌وجوی مستقیم.
- هر چرخهٔ اجرا: یک تغییر منطقی + یک اعتبارسنجی.
- گزارش نهایی: حداکثر ۶ bullet شامل تغییر، تست، ریسک باقی‌مانده و مسیر فایل‌ها.
- از بازخوانی فایل‌هایی که قبلاً بررسی شده‌اند و گزارش‌های طولانی خودداری کن.

## تقسیم کار

- کار کوچک (۱ تا ۳ فایل): یک ایجنت، بدون هندآف.
- کار متوسط: یک مجری + یک بازبین فقط پس از تغییر.
- کار پرریسک یا انتشار: مجری → security-analyst؛ بازبینی design فقط برای تغییر بصری.
- spark/aistudio/browser فقط وقتی درخواست واقعاً به آن ابزار نیاز دارد؛ برای کدنویسی عادی از آن‌ها استفاده نکن.

## قرارداد تحویل

```text
DONE
- تغییر: ...
- فایل‌ها: ...
- تست: ...
- ریسک/فرض: ...
```

اگر اجرا ممکن نیست:

```text
BLOCKED
- مانع: ...
- اقدام لازم از کاربر: ...
```

هیچ ایجنتی نباید صرفاً طرح، فهرست ایده یا گزارش تحقیق تحویل دهد وقتی می‌تواند تغییر را مستقیم انجام دهد.
